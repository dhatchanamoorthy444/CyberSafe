URL Anatomy

Scheme https

Path /verify-account

Recommended Action: Verify the destination independently before proceeding. Do not enter credentials.

Why This Matters

The hostname mimics a trusted brand.

The domain paypa1-security.example substitutes "1" for "l" in "paypal" — a classic lookalike technique. The actual destination is not PayPal.

The path signals credential harvesting.

Paths like /verify-account, /login, /confirm are commonly used in phishing pages to collect credentials.

HTTPS is present but not proof of legitimacy.

Transport encryption protects data in transit, but does not verify the identity of the destination. Phishing sites routinely use valid TLS certificates.

Recommended Action:

Do not enter credentials. Navigate directly to the official site by typing the URL yourself. Report the link if received via email or message.

Privacy & Safety by Design

CyberSafe is built on principles that protect you, not track you.

No Destination Requests

Suspicious URLs are never automatically opened, fetched, or pinged. Analysis runs on structure only.

Deterministic Authority

CyberSafe security rules are authoritative. AI explains findings but never overrides the deterministic verdict.

Secrets Stay Server-Side

VirusTotal, Groq, and Gemini API keys never leave the backend. Frontend receives only normalized results.

Local History

Scan history is stored locally in your browser. No accounts, no tracking, no cloud sync unless you opt in.

No Content Inspection

CyberSafe does not fetch page content, execute JavaScript, follow redirects, or inspect cookies.
